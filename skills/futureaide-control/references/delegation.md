# 向 FutureAide / DSH 派单

调用方负责理解目标、确定范围、分配工作和验收。执行会话承担明确授权的工作包。用户要求只读、规划、暂停或指定执行者时，遵守其范围；工具可用性不能代替授权。

## 发送前

- 核对 profile、绝对目录、普通 sessionId 和应用。独立对话可能共享同一目录，不代表文件隔离。
- 查询实际模型目录，按用户偏好显式选择供应商、模型和支持的思考档位。某次环境中的供应商名称不能写成通用默认。
- 读取目标项目规则和最少必要输入。宿主计划模式、审批、沙箱以真实结果为准。
- 同一文件指定一个写入负责人。独立工作可并行，有依赖或共享写入则按顺序执行。

## 自足工作包

```text
task_id / revision:
目标及成功标准:
当前阶段与授权范围:
profile / workspace / sessionId:
必要输入与已知事实:
允许修改的文件与唯一负责人:
保留行为、禁止触碰的内容:
验证方法、证据位置:
模型与成本约束:
停止条件、回传方式:
```

普通任务不填充无关字段，但新会话必须能独立理解输入和验收。工具名、模型和参数以当前运行时 schema 为准。

## 跟进与验收

使用稳定 request_id，默认 queue。授权纠偏才使用 steer，并明确被替代版本和停止动作。未知发送结果先查原回执，不能换 ID 重发。

执行者返回文件、命令、退出码、证据、未验证项和剩余问题。只读工作说明无修改；模拟模型与真实服务验证分别记录。

调用方按最新需求检查成果。工具成功、accepted、idle、执行者自报 done 均不代替验收。只缺证据时补证据，避免重复实现。

如需回调，先配置正确 Codex task ID，再由执行者调用该 profile 的 notify；证据文件必须在其工作目录内。缺少目标应报错，不能回落到其他任务。
